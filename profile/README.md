<p>住宅 IP 的“好不好”，讨论到最后总会落到四个参数上：纯净度、延迟、掉线率、并发能力。麻烦在于这四个词没有统一口径——同一家服务商标称 180ms，你实测 260ms，往往不是谁撒谎，而是采样点、目标域名、统计窗口都不一样。这篇按参数说明书的方式，把四项逐个给出定义、默认值、采样方法和判定边界，拿去就能照着测，测完也能横向比。</p>

<h2>一、评测口径：四个参数怎么定义</h2>
<p>先把定义写死，后面的数据才有意义。定义含糊的评测，结论只能当参考故事听。</p>
<h3>纯净度</h3>
<p>指出口地址在公开数据中的“可疑程度”，可拆成 ASN 类型、黑名单命中数、同段邻居密度三个子项。它不是单一数值，必须分开记录。</p>
<h3>延迟、掉线率、并发</h3>
<p>延迟取握手与首字节两个值；掉线率指单位时间内探测失败的比例；并发指同一出口可同时保持的活动连接数。三者都要注明采样时段，否则跨时段比较没有意义。</p>

<h2>二、纯净度：三个可量化指标</h2>
<p>这一项最容易被“纯净”两个字带偏。落到可核查的层面，就看三个数字。</p>
<h3>ASN 类型</h3>
<p>查询出口地址的 ASN，看 type 字段。isp 表示住宅/宽带运营商，hosting 表示机房。需要说明的是，部分 ISP 段也会承载托管业务，所以这一项要和 org 名称一起看。</p>
<h3>黑名单命中数</h3>
<p>用两到三个公开 DNSBL 查询入口交叉验证，记录命中数量。命中 1–2 个属于可接受范围内的噪声，命中 4 个以上建议要求替换。</p>
<h3>邻居密度</h3>
<p>供应商不一定公开，可以用“同 /24 内已知客户数”间接估算。这个数字超过 20 时，出口被牵连的概率会明显上升。</p>

<h2>三、延迟：采样方法与判读</h2>
<p>单次 ping 得到的数字没有统计意义，至少要 30 个样本，并区分握手与首字节。</p>
<h3>采样三原则</h3>
<p>同一目标域名、同一时段、同一台机器。换其中任意一项，结果就不可比。建议固定一个你业务里真实会访问的域名，而不是随便找个测速站。</p>
<h3>看中位数与 P95</h3>
<p>中位数反映常态，P95 反映最差的那 5%。两者比值超过 2 时，说明线路抖动明显，日常使用会有“时快时慢”的体感。</p>

<p>补一句实操细节：住宅出口的上游常与家庭宽带共享，晚高峰（当地 19:00–23:00）的延迟普遍比白天高 15%–30%，这属于正常波动，不必因此判定线路不合格。</p>

<h2>四、掉线率：观察窗口比单次数值重要</h2>
<p>掉线率的坑在于“测十分钟没掉”就下结论。短窗口只能证明当时没挂，证明不了稳定性。</p>
<h3>怎么统计</h3>
<p>用每分钟一次的 TCP 探测，连续跑 24 小时，统计失败次数占比。低于 0.5% 属于良好，0.5%–2% 需要观察，超过 2% 基本不能用于长会话。</p>
<h3>区分“真掉线”和“探测误判”</h3>
<p>目标站限流、DNS 解析失败、本机网络抖动都会被误记成掉线。建议同时探测两个不同目标，两者同时失败才算一次真实掉线。</p>

<h2>五、并发与带宽：端口、连接数与限速</h2>
<p>这三项经常被打包成一句“不限并发”，实际用起来才发现有隐形的连接数上限。</p>
<h3>端口数决定并行方式</h3>
<p>单端口意味着所有请求走同一条隧道，容易互相排队；多端口可以按业务分流，但也增加了配置复杂度。常见套餐给 1–5 个端口。</p>
<h3>连接数要看“活动连接”</h3>
<p>有些产品限的是同时保持的连接数而非请求数。浏览器开十几个标签就可能触顶，表现为部分资源加载失败。测试时用压测工具保持 50 个长连接跑十分钟，看是否被重置。</p>
<h3>带宽的口径差异</h3>
<p>标称 10Mbps 可能是峰值也可能是保证值，两者体验差很多。合同中确认是“独享保证带宽”还是“共享峰值带宽”，价格通常相差一倍以上，具体以报价为准。</p>

<h2>常见问答</h2>
<h3>延迟多少算合格？</h3>
<p>答：看目标服务的物理距离。美西到国内通常 150–220ms，美东 200–280ms，欧洲 250–350ms，属常见区间，仅供参考。超出 50% 以上建议复查线路。</p>
<h3>纯净度有官方评分吗？</h3>
<p>答：没有统一标准。各家评分模型的权重不同，只能作为参考。可靠做法是固定三个公开查询入口，自己记录一段时间的数值变化。</p>
<h3>掉线率高一定是服务商的问题吗？</h3>
<p>答：不一定。本地网络、DNS、目标站限流都会造成类似现象。先用两个目标交叉探测，再分段测试本地链路，能排除掉大半误判。</p>
<h3>并发数能协商提高吗？</h3>
<p>答：独享套餐通常可以谈，共享池基本不行。提需求时说明是“活动连接数”还是“每秒请求数”，两个指标的服务商理解经常不一致。</p>

<h2>合规提示</h2>
<p>本文给出的数值区间与测试方法用于技术评估，不构成性能承诺。实际表现受线路、时段与目标服务影响，请以自测结果为准。</p>
<p>压测与探测应控制强度，避免对目标服务造成干扰；不得将测试手段用于探测他人系统或绕过访问限制。</p>
